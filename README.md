# Arch Studio

내 컴퓨터의 코드 폴더를 읽어 아키텍처를 블록 다이어그램으로 만들고, 블록과 연결마다 기술 트레이드오프를 정리하는 로컬 웹앱입니다. 면접에서 "왜 이 구조인가"를 설명할 자료를 만드는 용도입니다.

## 실행

```bash
cd ~/arch-studio
npm start          # 화면 빌드 후 http://localhost:8790 실행
npm run serve      # 이미 빌드했으면 서버만 실행
```

OpenAI 키는 `.env`의 `OPENAI_API_KEY` 또는 화면 왼쪽 아래 AI 설정에서 넣습니다. 기본 모델은 gpt-4.1-mini입니다.

## 기능

- 코드에서 만들기: 폴더 구조, compose, package.json, 주요 소스를 읽고 AI가 블록 추론, 빠진 연결 검토, 트레이드오프 작성 3단계로 초안을 만듭니다.
- 편집: 왼쪽 블록을 끌어다 놓기, 블록 테두리 점을 다른 블록에 끌어 놓아 연결, 그룹 상자로 계층 묶기, 자동 정리(가로, 세로), 되돌리기(Cmd+Z), 복제(Cmd+D), Delete로 삭제.
- 트레이드오프: 블록과 연결마다 결정, 대안, 장점, 단점, 이유. AI로 채우기와 보강.
- 보드 개요: 요약, 왜 이 구조일 수밖에 없나, 시스템 수준 결정.
- AI 리뷰: 면접관 관점의 잘한 점, 약점과 보완, 예상 꼬리 질문과 모범 답변.
- 여러 프로젝트, 프로젝트마다 여러 보드(현재 구조와 대안 비교).
- 내보내기: PNG, 면접 노트 Markdown, 프로젝트 JSON.

## Cloudflare 배포본

주소: https://arch-studio.ewkimhyunsu11.workers.dev

- 아이디와 비밀번호로 가입, 로그인합니다(PBKDF2 해시, HttpOnly 세션 쿠키 30일).
- 가입하는 순간 배포 시점의 `data/projects/*.json` 이 그 계정의 사본으로 들어갑니다. 이후 수정과 삭제는 내 계정 사본에만 반영되고 다른 사람 화면은 바뀌지 않습니다.
- 데이터는 D1 `arch-studio`의 `projects(user_id, id)` 행에 저장됩니다. 같은 계정으로 두 창을 열면 로컬과 같은 방식(updatedAt 비교, 409)으로 덮어쓰기를 막습니다.
- 코드 폴더 분석은 서버가 내 컴퓨터 폴더를 읽어야 해서 로컬 버전에서만 됩니다. AI 리뷰와 트레이드오프 채우기는 각 계정이 AI 설정에 넣은 자기 키로 동작합니다.

```bash
npm run cf:deploy  # 화면 빌드, seed 묶기, D1 마이그레이션, 배포
npm run cf:dev     # 같은 구성을 http://localhost:8791 에서 실행
```

seed는 새로 가입하는 계정에만 들어갑니다. 로컬 아키텍처를 고친 뒤 다시 배포해도 이미 가입한 계정의 사본은 바뀌지 않습니다.

## 보안

- 서버는 127.0.0.1에서만 열립니다.
- `.env`, 키 파일, 인증서 파일은 읽지 않고, 읽은 본문에서도 키처럼 보이는 값은 가린 뒤 모델로 보냅니다.
- 프로젝트는 `data/projects/*.json`, 삭제한 프로젝트는 `data/trash/`, 설정은 `data/settings.json`에 있습니다.
